## Why Local Activation Is Separate

The installed development checkout contains unpublished subagent history
isolation checks not yet present in the public candidate. A bounded read-only
review identified the difference; the parent confirmed it in source. A direct
replacement would lose bounded-history validation and explicit full-history
approval. A passing candidate test suite cannot prove preservation of a local
feature that is not included in the candidate.

The safe next step is to port those protections into the schema-aware adapter,
test supported and unavailable history controls, exercise rollback on copies,
and only then activate approved files. Do not overwrite the candidate with an
older whole-file adapter or discard dirty local work. Backups and hashes remain
private. No live project policy or historical task evidence is changed.

One legacy project also has a missing manuscript route under both installed
and candidate checks. That pre-existing project issue remains visible rather
than being bypassed to claim global rollout success.

Exact-model qualification remains untested. Main promotion is not a stable
model certification, successful local activation, or external security audit.
